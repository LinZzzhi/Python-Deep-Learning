01 / REINFORCEMENT LEARNING 公网交互演示

基于强化学习的贪吃蛇系统

用 DQN 学习动作的长期收益，再由安全规划筛选可行方向，每走一格重新判断。

PyTorchDouble DQNFastAPI / WebSocket
决策原理 神经网络估计收益 · 路径规划筛选候选
01

状态表示与价值网络

贪吃蛇的十维状态构成
状态信息维度含义
食物相对位置2归一化的横向、纵向距离
四向危险4上、下、左、右是否会碰撞
当前朝向4用独热编码表示移动方向
10状态→64隐藏层→64隐藏层→4方向 Q 值

Q(s, a) 估计在状态 s 采取动作 a 后的累计折扣奖励。吃到食物获得正奖励，碰撞受到惩罚，模型由此学习方向的长期价值。

02

预判规划与动作筛选

  1. 吃食预判

    用时间感知 BFS 寻找食物路线，考虑蛇尾逐步让路。让虚拟蛇试走，检查吃完后是否仍能通向蛇尾；蛇较长时还检查空白区域连通性。

  2. 追尾周旋

    直接吃食不安全时，优先保留能通向蛇尾、可活动空间较完整的方向，等待身体移动后释放通道。

  3. 哈密顿锁定

    蛇较长或长时间未吃到食物时，尝试构建覆盖棋盘的闭合环。成功后保持蛇身沿环的顺序，并在安全范围内寻找捷径。

每步重新决策读取状态 → 规划器给出候选方向 → 选择候选中 Q 值最大的动作 → 移动一格
训练阶段 · 学习价值经验回放 + Double DQN

存储“状态、动作、奖励、新状态”，随机抽取经验训练。在线网络选动作，目标网络估值，以 Huber 损失修正预测，减少连续样本相关性与价值高估。

演示阶段 · 使用权重安全候选筛选 + 最大 Q 值选择

加载已训练权重，关闭随机探索，也不再更新网络。多个候选时由 DQN 排序；只剩一个候选则直接执行，下一格继续判断。

模型与规划器的分工

DQN 只接收 10 维局部状态，全局路线由规划器读取完整棋盘计算。默认表现来自二者配合；关闭规划仍保留单步合法动作过滤。Q 值是收益估计，不是成功概率。

环境：20 × 20 棋盘 / 4 个方向动作纯 DQN、预判规划与完美策略可在原版界面中对照。

02 / SIGNAL CLASSIFICATION 公网交互演示

雷达脉内调制样式识别

将 IQ 脉冲转换为时频图，利用卷积网络学习频率轨迹与调制类别之间的对应关系。

PyTorchNumPy / h5pySTFT-CNNFlask
识别原理 复数信号 → 时频表示 → 卷积分类
01

IQ 信号与时频变换

x[n] = I[n] + jQ[n]I、Q 为相互正交的两个分量，共同表示信号的幅度与相位。
短时傅里叶变换的处理步骤
处理步骤实现参数作用
分帧加窗Hann 窗 64 点
步长 32 点		在滑动的短时间段内分析信号
傅里叶变换64 点 FFT得到每个时间段的频率分量
功率映射|STFT|² → dB将各频率的能量分布转成图像强度

按每帧最大功率映射 40 dB 动态范围，再缩放为 96 × 96。时频图横轴为时间、纵轴为频率，亮度表示相对功率，保留频率随时间变化的轨迹。

02

卷积特征与类别输出

时频图→卷积 / ReLU / 池化 × 2→全连接

卷积提取局部纹理，池化汇总邻域特征，自适应池化统一到 7 × 7 后送入全连接层。模型从带标签的样本中学习纹理与类别的对应关系。

典型调制信号在时频图中的表现
信号示意时频轨迹
CW 单频近似水平的频率线
LFM 线性调频上升或下降的斜线
FSK 频移键控在离散频率间跳变

输出各类别得分，经 Softmax 转为相对分数，取最高分对应的调制样式。以上轨迹用于解释特征，实际分类由训练后的网络完成。

单脉冲识别读取 IQ → 校验长度与采样率 → 生成 STFT 功率谱 → CNN 推理 → 返回类别及各类分数
训练阶段 · 有标签监督时频图 + 真实类别 → 交叉熵损失

通过反向传播调整卷积与分类层参数，按验证集损失保存权重，最后用留出的测试集评估。合成模型与官方模型使用不同的类别集合和输入配置。

识别阶段 · 固定预处理8 类：1024 点 / 1 MHz
30 类：1000 点 / 50 MHz

加载对应权重，保持训练与推理的预处理一致。输入格式统一为 I、Q 两通道；拒绝全零、非有限值或长度不匹配的数据，不在识别时继续训练。

识别结果的适用范围

8 类合成测试准确率为 71.00%，官方 30 类小样本为 7.61%，后者仅用于流程演示。Softmax 分数未经置信度校准，最高分不代表一定正确，也不能据此保证未知信号可被可靠识别。

输入：.npy / .npz / 无表头两列 I,Q 的 .csvSTFT 参数相同；两种模型的输入配置及附加预处理分别随权重加载。

04 / INDEXED FILE SEARCH 本地 Web 应用

基于 SQLite 索引的文件查找器

以完整路径组织文件记录，通过文件名联合索引加速检索，数据保存在本地 SQLite 数据库中。

SQLite B-treeWITHOUT ROWID联合索引
索引结构 一张文件表 + 一个文件名联合索引
01

文件表 files

文件表字段及作用
字段类型作用
path主键TEXT完整路径，区分同名文件
nameTEXT文件名，使用 NOCASE 比较规则
is_dirINTEGER0 为文件，1 为目录

WITHOUT ROWID 直接以 path 主键组织表数据，省去额外的隐藏行号结构。NOCASE 默认处理 ASCII 大小写。

02

联合索引 files_name

CREATE INDEX files_name
ON files(name, path);
第一排序键 name→同名时按 path 排序
排序示意
notes.txt…/docs/notes.txt
report.pdf…/course/report.pdf
report.pdf…/work/report.pdf
report_1.pdf…/work/report_1.pdf
meta(key, value)元信息表：记录索引根目录、排除目录、构建时间，以及文件与目录条目数。
前缀查询name LIKE 'report%'

利用 B-tree 的有序结构，定位到一段连续索引范围，减少需要检查的条目。

任意位置匹配name LIKE '%report%'

通常仍需扫描候选条目，不能获得与前缀查询相同的范围定位加速。

覆盖索引的适用边界

当前查询还会读取 is_dir，而 (name, path) 索引不包含该字段，因此不能保证全程只读索引、不回表。

数据库结构依据实际建表与查询代码索引是文件名快照；新增、改名或删除后需要重建。
